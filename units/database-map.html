The database on one page

Four tables. The app adds rows to them; nothing ever changes or deletes a row. One visit is one row in sessions; everything that happened in it is in the other three. Each column shows its type: id text number time true/false. Any of them can be null: not known.

sessions
one row = one visit
session_id
id this visit
user_id
id a browser, not a person
app
text which app wrote the row
platform
text mobile or desktop
browser
text Safari, Chrome…
source
text from ?src= in the link
screen_w
number window width
started_at
time when the visit began
is_test
true/false your own runs
is_synthetic
true/false course practice data
session_id
clicks
one row = one tap
session_id
id the visit it belongs to
step
text the screen
overlay
text a layer open on top, if any
x, y
number 0–1 within the app's frame
seq
number 1st, 2nd, 3rd tap on that screen
hit
text what it landed on; none = nothing
created_at
time when
selections
one row = one choice
session_id
id the visit it belongs to
step
text the screen the choice was made on
label
text what the person pressed, as it reads on screen: Register, Next. For reading only: wording changes, so count with value
value
text what the system recorded: the screen it led to (register_email), what was opened (open:p02), searched (search:dog) or liked (like:p02, unlike:p02), or nothing for a button that does nothing (Share, Follow Jane, New post)
duration_ms
number time on the screen before choosing
created_at
time when
identities
one row = one sign-in
session_id
id the visit it belongs to
account
text a scrambled id: same account, same value; never the email
created_at
time when
task_runs
one row = one try at a task · from lesson 4
session_id
id the visit it happened in (joins to sessions)
task
text the task, in words, as the participant was given it
started_at
time when the task was shown
ended_at
time when it ended: the moment the goal was reached, or Give up; empty if the run was interrupted (page reloaded or closed)
ended_by
text success (the app ends the run itself when the goal is reached) or gave_up

What they pressed during the run is in clicks and selections: the rows of the same session_id between started_at and ended_at.

Four things people get wrong

user_id
Looks like: a person
It is a browser. One person on two devices is two; two people on one tablet are one.
a sessions row
Looks like: someone using the app
It is a visit. Some visits have no taps at all.
is_test · is_synthetic
Look like: the same flag
Test = your own runs. Synthetic = the course's practice data. Real visits have both false.
app
Looks like: always yours
It is whichever app wrote the row. Always filter on it.

Who may do what

The appAnyone who opens it may add rows. Never read, change or delete them.
You, signed inMay read rows. Never change or delete them.
Your analysisViews you build in the analysis space, on top of the raw rows.

Following one visit

Find the visit in sessions. Take its session_id. Collect every row with that session_id from clicks, selections and identities, and put them in order of created_at. That is the visit, tap by tap.
